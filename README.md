# YASOTHON WATER — โปรเจกต์สำหรับ deploy บน Vercel

ระบบเฝ้าระวังน้ำฝนและระดับน้ำ จังหวัดยโสธร พัฒนาโดย ฝ่ายส่งน้ำและบำรุงรักษาที่ 3
โครงการชลประทานยโสธร สำนักงานชลประทานที่ 7

## มีอะไรในโฟลเดอร์นี้

```
index.html      หน้าเว็บ (สถิต) — เรียกข้อมูลผ่าน /api/water แทนการยิงตรงไป ThaiWater
api/water.js    Vercel Serverless Function: พร็อกซี + กรองข้อมูลเฉพาะยโสธร + ตั้งแคช
package.json    ข้อมูลโปรเจกต์ขั้นต่ำ (ไม่มี dependency ให้ติดตั้ง)
```

ไฟล์ `yasothon-rain-monitor.html` (ไฟล์เดี่ยว เรียก ThaiWater ตรง ไม่ผ่าน proxy) ที่ส่งให้ก่อนหน้านี้ยังใช้ได้
เหมาะสำหรับเปิดดูเร็ว ๆ บนเครื่องตัวเอง แต่เวอร์ชันในโฟลเดอร์นี้ (`index.html`) คือเวอร์ชันที่ควร deploy จริง

## ทำไมต้องมี proxy (`api/water.js`)

ไม่ใช่เพราะติด CORS — ThaiWater อนุญาตให้เว็บอื่นเรียกข้อมูลตรงได้อยู่แล้ว เหตุผลจริงคือ:

1. **ลดขนาดข้อมูล** — endpoint บางตัวของ ThaiWater (`rain_today`, `rain_monthly`, `rain_yearly`, `analyst/dam`)
   ส่งข้อมูลทั้งประเทศ (1–4 MB ต่อครั้ง) ทั้งที่หน้าเว็บนี้ใช้แค่จังหวัดยโสธร (10–20 รายการ) proxy
   จะกรองให้เหลือเฉพาะยโสธรก่อนส่งกลับ ทำให้หน้าเว็บโหลดเร็วขึ้นมาก
2. **แคชที่ขอบเครือข่าย (Edge)** — proxy ตั้ง header `Cache-Control: s-maxage=...` ตามความถี่ที่ข้อมูลแต่ละ
   ชนิดเปลี่ยน (ฝนสด 2 นาที, รายเดือน/รายปี 1 ชม., อ่างเก็บน้ำ 15 นาที) เพื่อให้ Vercel แคชคำตอบไว้ที่ edge
   ผู้ใช้หลายคนพร้อมกันจะไม่ต้องยิงไป ThaiWater ซ้ำทุกครั้ง (ดูเอกสาร Vercel ด้านล่าง)
3. **จำกัดปลายทาง (whitelist)** — proxy ยอมส่งต่อคำขอเฉพาะ path ที่กำหนดไว้ล่วงหน้าเท่านั้น กัน endpoint นี้
   ถูกเอาไปใช้เป็น open proxy ยิงไปที่อื่น

อ้างอิงพฤติกรรมแคชของ Vercel:
- https://vercel.com/docs/functions/serverless-functions/edge-caching
- https://vercel.com/docs/caching/cache-control-headers

หลัง deploy จริง เปิด DevTools → Network → ดู response header `x-vercel-cache` ของคำขอ `/api/water...`
(`HIT` = ตอบจากแคช, `MISS` = เพิ่งไปดึงจาก ThaiWater) เพื่อยืนยันว่าแคชทำงาน — พฤติกรรมนี้อาจต่างกันไปตาม
แผนบัญชี Vercel ที่ใช้ ควรตรวจสอบเองหลัง deploy

## ทดสอบมาแล้วก่อนส่งให้

- `api/water.js` ผ่านชุดทดสอบแยกส่วน (mock ข้อมูลจาก ThaiWater): ปฏิเสธ path ที่ไม่อนุญาต, กรองจังหวัด
  ถูกต้อง, ส่งต่อ query เดิม, ตั้ง Cache-Control ตามที่กำหนด, คืน 502 เมื่อ ThaiWater ตอบผิดพลาด
- `index.html` ผ่านการทดสอบทั้งหน้าในเบราว์เซอร์จริง (Chromium) โดยรันเซิร์ฟเวอร์จำลองพฤติกรรม Vercel บน
  เครื่อง แล้วให้หน้าเว็บเรียก `/api/water` จริงและแสดงผลถูกต้องทุกแท็บ (ไม่ได้ทดสอบกับบัญชี Vercel จริง)

ยังไม่ได้ทดสอบ: การ deploy บน Vercel จริง, ปริมาณผู้ใช้พร้อมกันจำนวนมาก, พฤติกรรมแคชจริงบนบัญชีของคุณ

## วิธี deploy (เลือกวิธีใดวิธีหนึ่ง)

ผมไม่มีบัญชี Vercel ของคุณและไม่ควรกรอกรหัสผ่าน/เข้าสู่ระบบแทนคุณ จึงต้องให้คุณเป็นคนกด deploy เอง
เลือกได้ 3 วิธี:

### วิธีที่ 1 — ลาก-วางที่หน้าเว็บ Vercel (ง่ายที่สุด)
1. เข้า https://vercel.com/new
2. เลือก "Deploy" แบบไม่ผ่าน Git แล้วลากโฟลเดอร์นี้ทั้งโฟลเดอร์ (หรือไฟล์ zip ที่แนบมาด้วย) ไปวาง
3. Vercel จะตรวจพบ `index.html` และโฟลเดอร์ `api/` เองโดยไม่ต้องตั้งค่าเพิ่ม กด Deploy
4. เสร็จแล้วจะได้ลิงก์ `https://<ชื่อโปรเจกต์>.vercel.app`

### วิธีที่ 2 — เชื่อม GitHub (แนะนำถ้าจะแก้ไขต่อเรื่อย ๆ)
1. สร้าง repository ใหม่บน GitHub แล้วอัปโหลดไฟล์ในโฟลเดอร์นี้ทั้งหมด
2. เข้า https://vercel.com/new แล้วเลือก "Import Git Repository" เลือก repo นั้น
3. ตั้งค่าเป็นค่าเริ่มต้นได้เลย (ไม่ต้องระบุ Build Command เพราะไม่มีการ build) กด Deploy
4. ครั้งต่อไปแค่ push โค้ดใหม่ขึ้น GitHub, Vercel จะ deploy ให้อัตโนมัติ

### วิธีที่ 3 — Vercel CLI (สำหรับผู้ที่คุ้นเคยกับ command line)
รันบนเครื่องของคุณเอง (ต้องมี Node.js ติดตั้งไว้):
```
cd yasothon-water-vercel
npx vercel login      # เปิดเบราว์เซอร์ให้คุณล็อกอินเอง
npx vercel --prod
```

## ปรับสำหรับจังหวัดอื่น

แก้ค่าคงที่ต่อไปนี้ให้ตรงกัน (รหัสจังหวัด 2 หลักตามมาตรฐาน ThaiWater):
- `api/water.js` → `const PROVINCE = "35";`
- `index.html` → `const PROVINCE = "35";` (ค้นหาคำว่า `รหัสจังหวัดยโสธร` ในไฟล์)
